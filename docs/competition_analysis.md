# 赛题要求与模型开发路线

核对日期：2026-07-27  
赛题页面：[2026AIC·“AI＋钢铁”板材表面缺陷检测](https://www.aicomp.cn/tracks/tracks-1/4174.html)  
参考文章：[图像去模糊算法：循序渐进](https://cloud.tencent.com/developer/article/1350980)

## 1. 任务的真实边界

当前赛题不是 X 射线焊缝检测，而是高速轧制产线上的**钢铁板材表面缺陷目标检测**：

- 输入：典型 4096×3000、8-bit、单通道灰度 JPG/PNG；
- 标注：PASCAL VOC XML，绝对像素 `xmin/ymin/xmax/ymax`；
- 输出：全测试集预测汇总为一个 JSON 列表；
- 场景干扰：水渍、油污、粉尘、氧化铁皮脱落、正常水切痕迹；
- 核心难点：小目标、长条目标、长尾类别、跨产线分布偏移；
- 训练约 3200 张，初赛测试约 800 张，后续跨线测试约 1000 张；
- 赛事禁止商业闭源视觉 API、人工修改测试结果、测试集伪标签回灌和多模型无脑集成；
- 官方数据仅限本次竞赛的非商业研究，不能上传公开仓库或网盘。

网页给出的 9 个合并类别与数量：

| 类别 | 标签 | 数量 |
|---|---|---:|
| 结疤 | `jieba` | 604 |
| 纵裂 | `zonglie` | 296 |

`qilie` 与 `huashang` 明显是尾部类别。仅按框数量估算，头尾比超过 20:1。

## 2. 网页中必须进一步确认的歧义

这些问题不能靠猜，下载正式数据与赛题通知后要再次核对：

1. 正文说核心指标是 Precision/Recall，输出说明又说系统计算 mAP，但没有公布最终排名公式、IoU 阈值或类别加权方式。
2. Precision/Recall 公式在网页正文中未正常显示。
3. 网页示例用的是类别拼音，但正式 XML 可能存在大小写、旧类别名或其他拼写；程序遇到未知类别会直接报错，避免静默错标。
4. 边界框示例使用 `[xmin, ymin, xmax, ymax]`；需要确认坐标是否包含右下边界。当前工程按常见半开区间处理。
5. 黑盒验收提到统一 GPU 和时间限制，但页面没有给出具体显存、时限、容器格式与入口命令。
6. 页面写“PyTorch（建议 0 及以上版本）”显然是排版或版本号缺失，不能作为环境约束。

在正式训练前，优先读取赛道通知、下载包 README 和提交平台说明。

## 3. 截图算法与本工程的对应关系

截图的思想可以保留，但不建议逐字复刻网络名称。

| 截图思想 | 工程实现 | 原因 |
|---|---|---|
| 高分辨率切片 | 1024/1280 重叠滑窗 | 防止微小缺陷在整图缩放时消失 |
| Focal Loss | 自定义 Ultralytics Focal 分类损失 | 降低大量易负样本对梯度的主导 |
| 动态过采样 | 稀有类切片平方根反比重复，最多 3 倍 | 缓和 20:1 以上长尾，同时避免极端复制 |
| 主/辅双分支 | 单模型 P2/P3/P4/P5 四尺度头 | 结构更易复现，仍保留小目标与大目标通路 |
| 多尺度局部特征 | C3k2 + PAN-FPN | 在相邻尺度间双向融合 |
| 全局上下文 | SPPF + C2PSA | 利用背景结构区分真实缺陷与水油渍伪影 |
| 端到端后处理 | 内部边缘降权 + 原图坐标类内 NMS | 合并重叠切片预测并降低切断框 |
| 单模型部署 | 一套权重完成推理 | 遵守禁止多模型简单集成的约束 |

截图里的 GELAN、可变形卷积和聚合-分发模块有研究价值，但把多个新模块一次性叠入 3200 张数据的基线，会让收益归因、预训练权重迁移和黑盒复现更困难。先把切片、P2、长尾损失和验证划分做扎实，通常性价比更高。

## 4. 为什么不直接套用 2018 年去模糊文章

参考文章的关键结论是：模糊图像与清晰图像之间是卷积关系，恢复需要估计干扰/模糊核；文章作者也明确说明其“聚焦算法”没有开源，只链接了传统 FFT 反卷积和早期 DeblurGAN。

它不适合作为本赛题默认前处理，原因包括：

- 赛题页面说图像已完成 RAW 解码和对比度拉伸，没有说主要问题是运动失焦；
- 水渍、氧化皮和板材纹理不是模糊核，反卷积不能移除这些干扰；
- 错误模糊核会产生振铃，把背景边缘变成伪裂纹；
- 4096×3000 上逐图 FFT 盲去卷积成本较高；
- 对所有图统一锐化可能提升召回，同时显著降低精确率。

工程采用的替代：

1. 拉普拉斯方差判断是否确实模糊；
2. 只对低清晰度图像尝试有限强度；
3. 以 Tenengrad 梯度提升选择候选；
4. 以光晕像素比例限制振铃；
5. 功能保留为显式开关，但默认关闭；只有原图级 A/B 证明有效后才进入候选方案。

更推荐把高斯模糊、轻微运动模糊当作训练增强，让检测器学会对模糊不敏感。

## 5. 数据与验证设计

### 划分

文件名看起来包含钢卷/采集批次和 `RawXX` 连续帧。相邻帧很可能高度相似，因此不能随机按图片切分。工程按 `RawXX` 之前的组 ID 划分，降低同一钢卷泄漏到训练集和验证集的风险。

### 切片

初始建议：

- tile：1024；
- overlap：0.25；
- 最小可见比例：0.35，框中心落入切片时允许保留；
- 负切片比例：每张原图正切片数的 0.25；
- 稀有类最大重复：1（中性基线）；仅在长尾消融中测试 2/3。

需要特别观察：

- 细长纵裂被切成多个框是否影响评测；
- 位于大图边缘的框；
- 小于 8×8 或短边小于 4 像素的框；
- XML 尺寸与真实图片尺寸不一致；
- 无缺陷背景图是否存在以及比例。

## 6. 训练实验矩阵

不要同时改五个模块。建议按以下顺序记录每类 P/R/AP、宏平均和推理耗时：

| 实验 | 变化 | 目的 |
|---|---|---|
| E0 | YOLO11s，整图缩放 | 证明小目标损失程度 |
| E1 | P2 + 1024 切片 | 建立主基线 |
| E2 | E1 + Focal Loss | 降低易负样本影响 |
| E3 | E2 + 稀有类切片重复 | 提升 `qilie/huashang` 召回 |
| E4 | E3 + CLAHE | 验证局部对比度收益 |
| E5 | E3 + 门控去模糊 | 仅验证模糊子集 |
| E6 | E3 + 1280 tile | 测试上下文/显存权衡 |
| E7 | E3 + 每类阈值 | 在最终 P/R 目标上调优 |

最终阈值不应只用统一 `conf=0.25`。业务和赛题强调防漏检，初始推理阈值可降到 0.05–0.10，再按类别在验证集上搜索阈值；尾部致命类可以更低，但要监控伪影误报。

## 7. 训练完成后的质量门

提交前至少自动检查：

- 测试集每张图都成功处理；
- JSON 可被标准解析器读取；
- 所有类别名来自正式 XML 类别表；
- `0 <= score <= 1`；
- `xmin < xmax`、`ymin < ymax`；
- 坐标不越过原图；
- 没有 NaN/Inf；
- 空预测图片不会导致脚本报错；
- 单图超时、总显存和总运行时间符合黑盒要求；
- 代码、依赖、权重、启动命令可在干净环境复现。
