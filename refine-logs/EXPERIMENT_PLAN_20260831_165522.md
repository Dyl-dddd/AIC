# 钢板缺陷检测优化实验计划

**日期**：2026-08-31  
**目标**：在合规、可复现和有限算力下，提高真实原图的检测与尾类召回；不承诺未经验证的“最佳”或固定最终分数。  
**方法假设**：先修复数据/训练/评估闭环，再验证多尺度视图和长尾策略是否优于简单检测器。  
**本轮范围**：只读诊断、计划与任务清单；不启动新训练，不改动原始数据及历史权重。

## 1. 已确认事实与待验证假设

| 证据 | 发现 | 对计划的影响 |
|---|---|---|
| 旧实验 results.csv / 运行清单 | 两轮完成，76.30 分钟；逐轮 mAP50 0.789% → 1.096%；best 最终复验 1.083%，召回 3.476% | 仅作为流程试跑记录，不能证明方法有效 |
| ZIP 图像 SHA-256 定向复核 | 5 组/10 张字节完全相同的训练图；1 组跨 train/val，2 组跨 train/calibration，2 组仅 train | 旧划分存在确认的内容重复泄漏，必须重新建立 v2 划分 |

| 本地损失代码 + autograd 探针 | YOLO 使用质量软标签；当预测概率=目标0.1时，BCE梯度0，当前Focal梯度约0.00590 | 该Focal会改变软标签最优点；只是可信风险，不是已证实的低召回原因，需 BCE 对照 |
| trainer 与预算脚本 | batch=1、nbs=64，存在动态梯度累积；match_update_epochs.py 仅计 batch | 组件比较应记录真实 optimizer.step，不能把 batch 当优化器更新 |

## 2. 主张与成功判据

| 主张 | 最低证据 | 反例/反主张 |
|---|---|---|
| C1：适配尺度的视图/检测头可改善小框和长框检测 | 同一v2划分、同一预训练来源及预算；原图AP、按尺度召回和时延共同报告；stock 与 P2/视图对照 | 增益只来自更多样本、训练更新或泄漏 |
| C2：长尾策略能在误报可控时改善稀有类召回 | loss 与 repeat 分别改变；报告每类TP/GT、AP、FP/图，胜出候选再复验 | 靠降低阈值制造高召回，或牺牲总体性能 |

工程准入标准（不是赛事公布的分数线）：
- 小样本诊断：32–64个经复核正切片＋8个确定负切片；关闭随机增强，BCE在训练集合自身达到 AP50/召回约90%作为目标。达不到先检查原因，不扩大模型。
- 短训筛选：固定评估点观察学习趋势。若仍接近1%或大多数类持续零召回，返回诊断；不能仅凭5轮断定慢收敛架构无效。
- 组件晋级参考：开发集原图 AP50 增加至少1个百分点，或尾类召回增加至少2个百分点且总体AP下降不超过0.5个百分点、误报不过量增加；这些阈值在新实验前冻结。弱信号需重复确认，不等于统计显著。
- 最终结论：同协议、按采集组自助采样置信区间；预算允许时3个种子（42/2026/3407）报告均值/标准差，不挑最好seed当平均。

## 3. 五个核心实验块

### B0：数据、评估与训练正确性（必须先做）

**验证问题**：输入、标签、损失和输出坐标是否可信？
- 保留源ZIP只读、历史结果不覆盖；创建独立的 source_v2/normalization_v2/splits_v2。
- 以图像SHA、Raw采集组、候选C关联组组成连通分量，再分组划分。重复框按冻结规则处理；5组标签冲突先隔离再复核。
- 训练/测试内容重叠只用于防泄漏审计，训练侧关联组隔离；不利用测试样本做参数选择、伪标签或人工结果修正。
- 复核训练负样本抽样（至少50张）及9类训练框覆盖图，尤其是假负片、截断框、重复框、极小框和全局缩小后不可分辨目标。
- v2建议 train约75% / dev约15% / final_holdout约10%；分组与类别可行性优先于凑整数。每类报告目标数和独立组数，稀有类不足时明确不确定性。
- final_holdout不参与早停、checkpoint选择、阈值调整或人眼挑模型；若曾使用，降级为dev而非继续称最终集。
- 旧best/last可能见过v2 holdout内容，因此v2正式实验必须从公共预训练重新开始，不能续训旧试跑权重。
- 自定义原图 evaluator 用完美预测、重复预测、错类、空图、越界、长框、缺文件合成用例核验；与独立实现对齐共同定义，明确非官方评分复刻。
- 数据范围不全、缓存签名不一致、缺类异常、出现NaN/Inf时阻断正式结果入表。
- 对stock BCE、P2 BCE做小样本过拟合。仅在两者通过后测试当前Focal的同样本学习与梯度统计。

**门槛**：确认重复跨集合=0、所有隔离有清单、gold测试通过、小样本学习通过。未过，不启动全量长训。  
**输出**：私有审计JSON、v2清单与hash、诊断曲线、权重迁移报告。  
**预计**：代码/复核时间单列；小样本训练约0.3–1小时，实测调整。

### B1：建立能学习的简单基线（必须）

**比较**：
- R020：stock YOLO11s公共预训练 + BCE。
- R021：当前P2 + BCE，明确记录实际预训练覆盖；需要时采用经过测试的语义层映射。

**共同控制**：
- 相同v2原图、1024 tile/0.25重叠＋1024全局视图；repeat=1；不去模糊、不CLAHE、不MixUp。
- 初轮使用弱增强：无Mosaic/MixUp，轻微亮度变化与翻转；两个系统严格一致。
- 本机先检查batch=2能否稳定，再决定是否试4；保留显存余量，不自动降低输入尺寸或安装新驱动。
- 固定seed=42、优化器与学习率计划；记录每batch正样本、目标质量分数、梯度范数、真实优化器步数和BN微批大小。
- 初筛各5个epoch预算；在第1/3/5轮保存或评估原图dev。5轮只筛流程与学习趋势，不能包装成收敛结论。
- 若曲线仍明显向上且两个系统接近，仅选一条延长诊断，预算另计；重新设定长训日程，不从已剥离optimizer的best.pt假装无缝resume。

**决策**：以原图指标/时延共同选择；P2无实质收益可使用stock。  
**输出**：基线表、小/长目标召回、错误分解（定位/错类/低置信度/抑制/漏标）、耗时。  
**预算**：两条5轮，按本机旧实测折算约6–9小时含评估；新数据量与batch可能改变成本。

### B2：少量、单因素的收益验证（有基线后）

最多先批准3条5轮等价预算，每条只改变一个机制：
1. **损失对照**：BCE → 当前Focal（gamma=2/alpha=0.25）。重点验证软目标梯度、置信度和召回；若失败优先回退BCE，而非直接再叠注意力模块。
2. **采样对照**：BCE repeat=1 → repeat=3。保持真实优化器更新预算可比，报告额外样本曝光；不把多训练收益归因给算法。
3. **视图或背景策略二选一**：由错误分解决定。长框问题优先 tile-only vs tile+global；伪影误报优先有审核来源的训练难负样本，其他因素冻结。

条件候选（不自动排队）：
- 仅当loss和repeat各自有效，再验证交互项。
- 几何/亮度/轻度模糊增强、CLAHE、去模糊逐项试；优先根据训练/开发样本诊断，而不是全部开启。
- 1280输入、更多检测头、GELAN/可变形卷积/双主干暂后置；无收益删除复杂度。
- GC10额外预训练只有在同初始化、同预算比较中优于COCO后才保留；旧GC10两轮权重不是默认优选。

**门槛**：遵循第2节的开发集收益准则，弱信号延后确认；最终集始终封存。  
**预算**：最多3条×5轮等价，约9–13小时；全部无收益则停止扩展，保留最简单基线。

### B3：对胜出方案长训、校准与后处理（必须）

- 仅对胜出配置安排30轮起步、最多60轮第一阶段长训；学习率/暖启动按目标日程预先配置。
- 每轮视图验证监控健康；每5轮原图dev评估，单独保存best_original，不能仅按视图fitness挑最终模型。
- 记录收敛趋势；开发集10次有效评估无改善再考虑早停，具体频率和耐心在启动前冻结。
- 固定候选缓存比较同一权重NMS IoU=0.45/0.55/0.65；探索置信度截断0.001/0.005的AP敏感性。部署阈值只在dev校准。
- 同时报原图AP50/AP50:95、每类P/R、尾类TP/GT、Recall@FP/图（0.1/0.5/1.0）、预测数与端到端延迟。AP使用足够低统一候选门槛，不能靠阈值优化声称网络AP提高。
- 对长框/局部片段的重复抑制作独立对照；不盲目拼接相邻缺陷，不通过多checkpoint投票弥补模型问题。
- 150轮不预先承诺：当前速度估算单次150轮约95小时（近4天），应先看30/60轮曲线。

**预算**：30–60轮约19–38小时训练/逐轮验证，加原图评估后约20–41小时。  
**失败解释**：训练集高、dev低检查泛化；两者低回查学习/标签；长框低检查视图与合并，小框低检查有效像素与分配。

### B4：独立验证、稳健性与交付（必须；多seed条件执行）

- 选模、阈值和后处理冻结后才评估final_holdout；只报告、不在此处调参。
- 对现有可证实采集域做留域诊断；“按文件名前缀分域”只是代理，不等于已证明跨产线泛化。
- 预算允许：最终方案3seed，至少对照基线与候选seed一致；资源不足明确单seed/有限证据，不伪造稳定性。
- 只用一个确定checkpoint生成全部669张测试图结果，统计成功图数、零预测图数、失败图数；禁止用训练标签填补那张重复测试图的结果。
- 自动校验提交JSON、类名、边界、有限分数、缺图、CPU/GPU耗时与复现环境。不要自动上传或提交。
- 固定依赖版本与权重/代码/清单hash；不在比较中途升级Ultralytics。
- 若最终需要全训练集重训，预先固定训练轮数/阈值策略，明确此新权重不再有未接触的本地holdout成绩。

**预算**：一次最终原图评估预计0.2–1小时，实测为准；额外2seed×30–60轮约38–76小时，另行批准。

## 4. 统一评估与选择协议

- 主表只收 scope_complete=true 的原图级真实GT结果，并记录数据/评估器版本。
- 当前官网同时强调P/R与mAP，未给出完整IoU/排名公式和基础P门槛；因此AP50/AP50:95与召回/误报并列，不能私称任一项为官方最终总分。[赛题说明](https://www.aicomp.cn/tracks/tracks-6/4174.html)
- 开发集可以用于checkpoint选择和阈值校准，但不能再称“untouched val”。置信区间按组重采样，不把同原图切片当独立样本。
- 同一组件对照保持split、初始化来源、微批/有效batch、增强、评价频率、候选置信度一致。采样/视图改样本数时，修正当前等步数工具并直接记录optimizer.step。
- 有标签冲突和泄漏治理变更就提升数据版本；旧1.08%与新v2分数不是纯算法提升对照。
- 无同数据同协议baseline，不与GC10或网上不可复现实验数字做直接横比。

## 5. 执行里程碑与预算

| 顺序 | 里程碑 | 放行条件 | 占机时间估计 | 当前状态 |
|---|---|---|---|---|
| M0 | 数据v2、评估器gold测试、32–64样本学习 | 隔离与gold测试通过、能拟合干净小样本 | GPU约0.3–1h；开发时间另计 | 待实施 |
| M1 | stock BCE / P2 BCE 初筛 | 有真实学习趋势，评估完整 | 约6–9h | 受M0阻挡 |

本机粗略核心路线约35–65小时占机时间，额外seed约38–76小时；不是一次性全部启动的承诺。以本次2轮76.30分钟（约0.636小时/轮）为参考，新数据规模、有效batch、stock/P2和温度会改变速度。先完成M0/M1再更新预算。云平台需明确GPU型号、环境、存储和用户授权后重新实测，不擅自租卡/上传机密数据。

## 6. 有意不做的事项

- 不以旧低分为由马上堆双主干/Transformer/GELAN等组件。
- 不把漏检修复等同于无限降低置信度；不把loss下降等同于可用检测。
- 不将缺陷图/标注发往公开服务或商业闭源视觉API；不把测试图、伪标签或人工修正结果回灌。[数据与算法约束](https://www.aicomp.cn/tracks/tracks-6/4174.html)
- 不自动运行旧 run_experiments.py 全矩阵：当前它把best.pt存在当完成，且旧实验预算/数据版本不满足本计划。
